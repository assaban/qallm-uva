# QALLM audit, June 2026

A full audit of the project as it enters its final phase: what is solid, what
carries risk, the web-UI assessment, and a prioritised punch list. Written to be
honest, an audit that only lists strengths is not an audit.

## Headline assessment

QALLM is in strong shape. The pipeline is complete and runs end to end; the
measuring instrument is calibrated (5/5 reliability recall on the lab set with
near-zero false positives on clean code); the trustworthy-and-defensible tier of
the roadmap is done (calibration, confidence intervals, mutation-based
confidence, test-quality metric, RQ2/RQ3 plumbing, provenance). The codebase is
clean: 719 passing tests, ruff clean, no stale TODO/FIXME markers. The remaining
work is finalisation, a confirm-path bug, targeted coverage, and the web-UI
catch-up, plus the headline experiment run itself.

## What is solid

- **The method and its guards.** Round-0 measurement, the baseline gate, the
  incoherent-oracle filter, the correctness oracle with body withheld, and
  repair-on-verification-failure are all implemented, tested, and documented in
  the methodology-decisions log. The verdict is defensible.
- **Calibration.** The lab set with its answer key is a real instrument; the
  calibration journey (and the chain of bugs it surfaced) is documented and is
  itself a methodological strength to present.
- **Statistical rigour.** Bootstrap 95% CIs are wired into the aggregate.
- **Confidence.** Mutation-based oracle confidence is implemented and wired; it
  is the project's strongest answer to "are the bugs real?".
- **Reproducibility.** Every run stamps a provenance manifest (commit, model,
  environment, dataset fingerprint).
- **Engineering hygiene.** Reviewable PRs, append-only logs, parallel resumable
  runner, clean lint, growing test suite.

## Risks and open issues (prioritised)

### P0, blocks RQ2/RQ3 results

- **The confirm path maps zero findings to functions.** On the lab full run, RQ2
  read 0 confirmed / 0 refuted even though `security_findings.py` has Bandit
  findings. The round_00 baseline fix is working (the baseline is found), but
  findings are not being adjudicated. Diagnostic logging is now in place
  (`confirm_verify`); the next `--confirm` run will show whether findings are
  absent from the round-0 `static.json`, or present but unmapped (line 0 /
  module-level). This must be resolved before RQ2/RQ3 can be reported. Likely a
  one-area fix once the log pinpoints it.

### P1, affects the confidence story

- **Mutation confidence yields "unknown" for low-structure functions.** Some
  correct-but-trivial functions (e.g. `accumulate`: append and return) have too
  few mutable sites to produce a viable mutant, so they score "unknown". This is
  honest (the oracle cannot be stress-tested if there is nothing to mutate), but
  it should be explained in the write-up rather than read as a failure. The
  recent operator expansion (%, //, **) and the source-presence fix reduced the
  spurious "unknown" count materially; the residual is genuine.

### P2, robustness for the dataset run

- **Broad excepts: 44 sites** (up from the audit's earlier 33). Most are
  defensible isolation (one bad notebook must not sink a batch), but the count is
  growing and should be triaged: keep the isolation ones, narrow or at least log
  the rest, so a silently swallowed error during the headline run is not mistaken
  for a clean result. (Roadmap item 6.)
- **Coverage holes in load-bearing code.** Overall coverage is 79%. The analyser
  finding-shape is now well pinned (recent work). Still thin: `generator.py` and
  `repair_manager.py` (core pipeline), the LLM providers (integration-bound), and
  `stats.py` (38%). The providers are acceptable to leave (they need live APIs);
  `generator`/`repair` are worth raising (roadmap item 7) because they produce
  the RQ1/RQ3 numbers.
- **Entry-point scripts at 0%** (`run_qallm.py`, `experiment.py`, `loop.py`,
  `hypothesis_baseline.py`). Lower priority (thin glue or alternate baselines),
  but `hypothesis_baseline.py` should be confirmed as either used or removed so
  it does not confuse a reader of the repo.

## Web UI assessment

The UI exists and is reasonably complete: screens for the Gap, Experiments,
Sessions, Improvement, Docs, and About, served over a FastAPI backend with a
`/api/metrics/aggregate` endpoint. It is a genuine inspection surface, not a
mock. Two gaps, both worth closing for the demo:

1. **The new confidence data is not surfaced.** The aggregate now carries
   `gap_confidence` (distribution + high-confidence count), but the UI types only
   have a per-finding `confidence` number and no view renders the distribution.
   For the demo, the gap panel should show "X gap findings, Y high-confidence",
   which is the single most compelling number we have. Small frontend change
   against data the API already returns.
2. **Provenance is not shown.** The manifest now has a provenance block; a small
   "run details" affordance (commit, model, dataset fingerprint) would make the
   tool visibly reproducible to a committee, and costs little.

Neither is blocking; both are high-impact-per-effort for the dissemination goal
(Tier 3). Recommendation: do (1) before any live demo; (2) is a nice-to-have.

Beyond these, Tier 3's in-app Architecture page and a live metrics page (pull the
real aggregate once E1 is done) remain the planned dissemination work.

## Documentation state

Strong. Concepts, architecture, guides, experiments, and a thesis folder
(scaffold, structure-and-plan, experiment-plan, methodology-decisions,
roadmap, session log, status update) are all present and current. The
append-only methodology and session logs give the defensibility trail an
examiner will want. No action needed beyond keeping them current.

2. **(P1) Run E1** (the ENVRI headline) for the gap rate + CI + confidence.
3. **(P2) Triage the broad excepts**; raise `generator`/`repair` coverage.
4. **(Tier 3) Surface `gap_confidence` in the gap panel**; then the
   Architecture and live-metrics pages.
5. **(hygiene) Resolve `hypothesis_baseline.py`/`loop.py`** as used or removed.
6. **Draft the write-up now** for everything that does not need results
   (Background, Method 3.1 to 3.9, Implementation, Setup, Threats, Appendix).

## One-line verdict

The instrument is sound and the engineering is clean; the path to "done" is a
confirm-path fix, the headline run, a UI confidence view, and disciplined
write-up of material that is already ready to write.
